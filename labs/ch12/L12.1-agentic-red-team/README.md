## Brief

On Tuesday 2 February 2027 a support ticket carried text hidden from people and aimed at a pilot summary feature.
The pilot's model wrote a Markdown image whose address carried other customers' contact details, and a support
engineer's browser fetched it when the summary was shown. Chapter 12 tells the story (a composite).

You have what Relay built afterwards: **Relay 4.26.0** in `relay-repo/`. Ticket text reaches the model in a
spotlighting envelope, summaries are plain text from an allowlist of characters, untrusted text renders without
images or outside links, an agent run that reads untrusted text is tainted, the email adapter sends only to
Relay's directory, memory facts are untrusted by default, and the egress proxy allows only Relay's repository on
the GitHub hosts and terminates any other server name.

This lab does **not** attack a model, and it does not measure an attack success rate. Measuring that needs a
red-team exercise against the deployed model. Instead you build the **control matrix**: for each attack class in
the threat model, which controls are claimed against it, and whether each one, run on Relay's own artefacts,
stops every variant of the class and still lets an end-to-end legitimate case through. You count coverage by
**failure domain**, the code each control depends on, find what the failure of one domain does, and run the gate.
On 4.26.0 the gate fails, honestly, on three classes; you will see why.

**About the data.** Everything in `data/` is generated by `scripts/generate_data.py`. The 14 attack classes are
**structured records**: an effect, a channel, a technique label, framework labels and a target under the reserved
`attacker.example` domain. Each `payload` is an **inert placeholder**, such as
`[[INJECTION technique=hidden-text effect=exfil-via-image-link encoding=zero-width]]`. It names a technique and
contains no instruction text, on purpose: a book should not ship reusable attack strings, and the probes do not
need one, because they test whether an effect *can* happen, not whether a model would try. Chapter 12 explains the
techniques with citations. Framework IDs (OWASP, MITRE ATLAS) are labels to confirm at the source before use.

## What you will practise

- Writing a **threat model** with trust boundaries for prompts, context, tools, memory and outputs.
- **Verifying a control** by running it, with a legitimate case beside each attack class.
- Counting **independence by failure domain**: two controls that depend on the same code share a failure.
- Telling **blocking**, **mitigating** and **latent** controls apart, and keeping the last two out of the count.
- A **coverage gate** that passes or fails from evidence, and a G4 row that also needs deployment evidence.

## How the tests choose what to grade

Tests run against `starter/` by default. To check the reference, in bash: `LAB_TARGET=solution python -m pytest -q`.
In PowerShell: `$env:LAB_TARGET="solution"; python -m pytest -q; Remove-Item Env:LAB_TARGET`. The variable persists
until it is removed, so always remove it, or later runs will silently grade the solution. Run pytest from this lab's
folder.

Until you finish, failing tests stop with `NotImplementedError`. `tests/test_probes.py` and
`tests/test_data_relay.py` exercise provided code and Relay itself, so they pass from the start.

## Troubleshooting

- `NotImplementedError: TODO n` — expected until you implement TODO n.
- `ModuleNotFoundError: relay` — run from `starter/` or `solution/`; `redteam/__init__.py` adds `../relay-repo/src`.
- Results differ from the chapter — check `LAB_TARGET`, rerun `python scripts/generate_data.py` and `git diff data/`.

## Known limits

The probes show that each control stops every variant in its set. A variant set is not every possible attack, and
the probes cannot show how often a model tries, which is the attack success rate; that needs a red-team exercise
against the deployed model (open item, owner aisha.r). The egress probe evaluates a model of the proxy built from
the committed `squid.conf` and its lists; it does not start Squid, so egress counts as not deployed. Judge
isolation is a lab model of Chapter 7's rule and is mitigating. Failure domains are declared in `controls.json`,
not derived from the code, so a shared dependency nobody declared is invisible. The 4.25.0 view runs 4.26.0's
code with the newer controls switched off; approval, the tool allowlist and memory review behave the same in both.
