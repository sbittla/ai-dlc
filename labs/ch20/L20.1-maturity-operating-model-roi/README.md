## Brief

In July 2026 leadership funded a rollout of coding agents to the four product teams beyond Relay (Chapter 1). The
engineering director held it until the teams had a baseline. By June 2027 the company has a baseline quarter, an
acceptable-use policy, an approved tool catalogue and a thirteen-week pilot in two teams (Lab 20.2). The AI governance
council now has to decide on a twelve-month rollout.

Three drafts are on the table. The team leads' self-assessment says most teams are at level 3 of 4. A sponsor's
catalogue and policy draft bans unapproved tools and lets a requester approve their own tool. A sponsor's ROI draft
takes a vendor's "38% faster" as a measured input and counts lines of code as a benefit.

You will build the checks that turn these drafts into evidence the council can rely on: maturity scored only from
evidence, the catalogue and policy checked against Relay's own records, and an ROI model that keeps measured values
apart from projections and shows which assumption moves the answer most.

**About the data.** Everything in `data/` is **generated** by `scripts/generate_data.py` and labelled, except the
three files in `data/catalog/relay-4.30.0/`, which are copied from canonical Relay 4.30.0. The company, its teams,
its people outside Relay and every number are fictional. The pilot's measured inputs are copied from Lab 20.2's
`roi-inputs` report, whose data is simulated with configured effects. `docs-browser-mcp` is a fictional tool server,
and its hash is a stand-in. Prices and costs are dated assumptions for June 2027.

## What you will practise

- Scoring **readiness and maturity** from evidence, so that anyone holding the same register gets the same levels.
- A **target operating model** with one accountable person per capability and an independent measurement owner.
- An **approved tool and MCP catalogue** and an **acceptable-use policy**, checked against Relay's pins and registry.
- An **ROI model** that marks every input measured or projected, refuses vendor numbers and output metrics, and
  shows its sensitivity as a tornado.

## How the tests choose what to grade

Tests run against `starter/` by default. In bash: `LAB_TARGET=solution python -m pytest -q` checks the reference. In
PowerShell: `$env:LAB_TARGET="solution"; python -m pytest -q; Remove-Item Env:LAB_TARGET`. Always remove the variable
afterwards, or later runs will silently grade the solution. Until you finish, failing tests stop with
`NotImplementedError`.

## Steps

### 1. Read the brief and the data (15 min)

Read Sections 20.1, 20.2 and 20.5 of the chapter. Open `data/maturity/model.json` and one evidence register. Note
which evidence types each criterion accepts, and that a company-wide item (team `*`) counts for every team.

### 2. Maturity from evidence: TODO 1 (35 min)

Implement `criterion_met` in `maturity.py`, then:

```bash
cd starter
python -m adoption.report maturity --register 2027-01 --explain relay
python -m adoption.report maturity --register 2027-06 --explain analytics
```

In how many cells did the self-rating exceed the evidence in January, and in June? Pick one inadmissible item in
January's register and say what evidence would replace it. Why does analytics stop at level 2 in culture in June,
although its team ran the survey?

### 3. The operating model (15 min)

```bash
python -m adoption.report tom --draft
python -m adoption.report tom
```

Read `tom.py`. For each of the draft's seven findings, say what would go wrong in the first year. Why must the
measurement owner sit outside the sponsor's line?

### 4. The catalogue and the policy: TODO 2 (35 min)

Implement `check_catalog` in `catalog.py`, then `python -m adoption.report catalog --draft` and
`python -m adoption.report catalog`. Which draft finding would have recreated shadow AI? Which would have let a
repository run a tool server nobody reviewed? Why does the security list come from the operating model rather than
the catalogue? Why does CAT007 ask whether a tool runs unattended instead of trusting its `kind`? Compare
`data/catalog/relay-4.30.0/` with Chapter 3's allowlist and Chapter 13's AI components record, and the February
catalogue (`catalog-2027-02.json`) with the June one.

### 5. ROI inputs: TODO 3 (25 min)

Implement `check_inputs` in `roi.py`, then `python -m adoption.report roi --draft`. The draft is refused. Rewrite its
three worst inputs as they should be, with a status, a source and a range. The banned-metric check is a word list:
name one output metric it would miss, and say how a reviewer would catch it. The check also cannot tell whether a
measured value is the one its reference printed; find the test that does this for the pilot's values.

### 6. Sensitivity: TODO 4 (20 min)

Implement `tornado`, then `python -m adoption.report roi` and `python -m adoption.report plan`. Which two inputs move
the year-one net most? Which of them is measured, and could a longer pilot narrow it? Where does the steady-month
break-even sit against the pilot's interval for author hours saved?

### 7. Write it up (35 min)

```bash
python -m adoption.report maturity --register 2027-06 > ../evidence/maturity-2027-06.md
python -m adoption.report roi > ../evidence/roi.md
```

On Windows PowerShell 5.1, use `| Out-File -Encoding utf8 ../evidence/roi.md` instead of `>`. Copy the three
templates into `evidence/` and complete them. The ROI memo must give the council a decision it can act on, with the
measured and projected parts kept apart.

> In January the self-ratings exceeded the evidence in 29 of 30 cells; in June, 14. Relay itself had no
> acceptable-use policy in January, so its security level was 1 despite drilled kill switches; in June it is 2,
> because an unregistered refund agent ran in March. The ROI keeps eight measured inputs apart from ten
> projections. At the pilot's measured savings the first year costs more than it releases (net -$106,445), and a
> steady month after the rollout is close to break-even (-$3,450). The two largest swings are author hours saved
> and the change fail rate difference, both measured, both with wide intervals.

## Troubleshooting

| Symptom | Likely cause |
| --- | --- |
| Every team is at level 1 | Company-wide evidence has team `*`; include it for every team. |
| Relay's data dimension looks too low | It is right: the AI-assisted label was last measured in July 2026, beyond 180 days. |
| CAT006 fires twice for one server | Expected in the draft: one for the reviewed record, one for Relay's `.mcp.json`. |
| CAT002 fires on the prohibited entry | Only approved or trial entries need an independent security approver. |
| CAT002 fires on every entry | The security list comes from the operating model's `security_people`, not the catalogue. |
| CAT007 fires on `ide-completion` | Only entries that run unattended need a case; `runs_unattended` must be a boolean. |
| ROI004 fires on the seat price | Contract and baseline counts may have low equal to high; pilot measurements may not. |
| ROI002 fires on every measured input | Compare the reference's start with `KNOWN_REFS`. |
| The tornado lists `engineers` | Skip inputs whose low equals their high. |
