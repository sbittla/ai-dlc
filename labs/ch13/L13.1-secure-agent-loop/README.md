## Brief

On Thursday 14 January 2027 a coding session prototyping a token verifier ran `pip install` on a package name
it had invented. An attacker had registered that name six weeks earlier. Its setup script ran during the install
and sent the session's environment, including a one-hour GitHub App token, to a repository the attacker
controlled. Chapter 13 tells the story (a composite).

You have what Relay built afterwards: **Relay 4.25.0** in `relay-repo/`. Its new `supply-chain/` folder admits
packages to a private mirror one project at a time, its lock files are pinned by hash and refuse source
distributions, every image is pinned by digest (closing Chapter 3's waiver WS023), and `tools/supplychain.py`
checks all of it. `security/` holds the gate policy, Relay's Semgrep and gitleaks rules and the suppression file.
`tools/sbom.py` writes the release's SBOM and AI-BOM. The deployed service and worker are wired to the code
(ADR-031).

You will build the gates an agent's changes must pass: the gate decision with reviewed suppressions, the
dependency gate, re-verification of the agent's fixes, the catch-rate report, and the release-evidence check.

**About the data.** Everything in `data/` is **generated** by `scripts/generate_data.py`, deterministically. The
160 agent changes are simulated: 100 carry one seeded weakness each, in twelve categories, and 60 are clean. The
Semgrep, gitleaks and Trivy reports are **simulated SARIF**. Which seeded weaknesses each scanner finds, and its
false alarms, were **configured** in the generator, so the catch rates show how to measure a gate, not how good
the real tools are. The mirror and the public index are local fixtures; the attacker's packages are metadata
with no code, and the "credential stealer" is a sentence. The release bundles are signed with an HMAC standing in
for Sigstore, with a published key, so they show the checks, not cryptographic strength.

**Do not install the package names in this lab.** They are invented (each returned 404 from PyPI's JSON API on 2026-11-08), and printing them makes them a ready-made list: anyone can register an unused name, which is the attack this chapter describes. Report any that appear on a public index to its security contact.

## What you will practise

- Deciding a **gate** from several scanners' findings, with suppressions that need a person's review.
- A **dependency gate** that catches hallucinated names, typosquats and dependency confusion before install.
- **Re-verifying** an automated fix instead of trusting its claim.
- Reporting a **catch rate** with an interval, by category and by stage, and saying what escaped.
- Checking **release evidence**: signature identity, transparency log, digests, SBOM and AI-BOM completeness.

## How the tests choose what to grade

Tests run against `starter/` by default. To check the reference, in bash: `LAB_TARGET=solution python -m pytest -q`.
In PowerShell: `$env:LAB_TARGET="solution"; python -m pytest -q; Remove-Item Env:LAB_TARGET`. The variable persists
until it is removed, so always remove it, or later runs will silently grade the solution. Run pytest from this lab's
folder.

Until you finish, failing tests stop with `NotImplementedError`. `tests/test_data_relay.py` and the test of the
provided Wilson interval pass from the start.

## Steps

### 1. Read the incident and Relay 4.25.0 (20 min)

Read Chapter 13's opening incident, ADR-028 and ADR-029, and `relay-repo/security/gates.json`. Then:

```bash
cd starter
python -m secloop.report incident
cd ../relay-repo && python tools/supplychain.py && cd ../starter
```

The incident report needs TODO 2; until then it stops with `NotImplementedError`, which is expected. Which three
facts about the package should have stopped anyone, and which of them can a tool check?

### 2. The gate: TODO 1 (40 min)

Implement `suppression_problem` and `decide` in `gates.py`; the docstrings are the specification. Then look at one
change and at the false alarms:

```bash
python -m secloop.report gate AC008
python -m secloop.report alarms
```

Why is a suppression bound to a fingerprint rather than to a file? Why may an agent never be the reviewer, even of
a true false alarm?

### 3. The dependency gate: TODO 2 (45 min)

Implement `check_requirements` in `deps.py`. Run `python -m secloop.report incident` again. Then explain why the
pinned, hashed `pyjwt==2.3.0` passes this gate, and which scanner reports it instead.

### 4. Re-verify the fixes: TODO 3 (35 min)

Implement `verify_fix` in `fixes.py`, then `python -m secloop.report fixes`. A rescan alone accepts 17 bad fixes:
which kinds, and why does each one look clean to the scanner?

### 5. Catch rates: TODO 4 (35 min)

Implement `catch_report` in `catch.py`, then:

```bash
python -m secloop.report catch > ../evidence/catch.md
```

On Windows PowerShell 5.1, `>` writes UTF-16; use `| Out-File -Encoding utf8 ../evidence/catch.md` instead.
Which category escapes most, and what control covers it instead? Why is the interval for the 4 IaC changes not
worth quoting?

### 6. Release evidence: TODO 5 (35 min)

Implement `check_release` in `release.py`, then `python -m secloop.report release`. RC-4 and RC-5 are signed
correctly. What does that tell you about what a signature proves? Generate the real BOMs for 4.25.0:

```bash
cd ../relay-repo
python tools/sbom.py --image-digest sha256:8d0eeba9d26884f38d5e97f75f1314f80ab8e7b6b7999544d4b484ecbe300b0c --date 2027-01-28 --out-dir ../evidence/dist
```

### 7. Relay 4.25.0 and the workspace audit (20 min)

From `labs/ch03/L3.1-accountable-workspace/solution/`:

```bash
python -m audit.report --policy ../data/policy.json --as-of 2027-01-28 --fail-on high ../../../ch13/L13.1-secure-agent-loop/relay-repo
```

It should report 0 open and 0 waived: WS023 is closed, not waived. Read `relay-repo/infra/compute.tf` and
`infra/db/roles.sql`. What does the worker now run, as which role, and what can it not do?

### 8. Review (10 min)

Fill in `templates/dependency-review.md` for a package of your choice, as if it were proposed for the mirror, and
`templates/gate-review.md` for your catch report.

## Optional live mode

`SECLOOP_LIVE=1 python -m secloop.live` (PowerShell: `$env:SECLOOP_LIVE="1"; python -m secloop.live;
Remove-Item Env:SECLOOP_LIVE`) runs Semgrep, gitleaks and Trivy, if installed, on `relay-repo/` and gates their SARIF.
Cost $0; nothing is installed for you. A missing tool or an error is recorded and the gate exits 2. It never runs in
the tests, and its results are not in the chapter.

## Troubleshooting

- `NotImplementedError: TODO n` — expected until you implement TODO n.
- Results differ from the chapter — check `LAB_TARGET`, then rerun `python scripts/generate_data.py` and
  `git diff data/`; the data must not change.
- `UnicodeEncodeError` on Windows — set `PYTHONIOENCODING=utf-8`.

## Known limits

The scanners are simulated, so the catch rates are properties of the generator's configuration. The release
signature is an HMAC with a published key. The hashes and digests in Relay 4.25.0 are lab stand-ins in the right
form. The deployed service still needs a PostgreSQL store adapter, so the environment carries no traffic.
