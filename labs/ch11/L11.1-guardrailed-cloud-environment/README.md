## Brief

On a Friday in November 2026 an engineer built a lab environment by hand to try a self-hosted model, and left it running until Monday: 66 hours, about $2,289 at list prices, with the model server and a database reachable from the internet. Chapter 11 tells the story (a composite).

You have the environment Relay built instead, as code: **Relay 4.21.0** in `relay-repo/`, whose `infra/` folder is the OpenTofu configuration of Relay's private, non-production environment on AWS (ECS Fargate, RDS PostgreSQL with a standby, Secrets Manager, a private endpoint for the model API, an egress proxy, budgets), and whose `infra/org/` holds the organization's guardrails. You also have the plan of that configuration, the weekend lab reconstructed as a plan, 16 seeded variants, five destroy plans and two post-teardown inventories.

You will build the checks that stand between a pull request and an apply: twelve policy rules over the plan, a cost estimate from a dated price table, and a teardown checker. Then you will measure them on the seeded plans, including the ones they cannot see.

**About the plan files.** `data/plans/*.json` are in the JSON format that `tofu show -json` prints. They were **generated** by `scripts/generate_data.py` from a small model of each resource, written to match `relay-repo/infra/*.tf`, **not produced by `tofu plan`**. They keep the parts of the format the checks need (`resource_changes` with `before`, `after` and `after_unknown`, `configuration` with references, `variables`) and say so in `terraform_version: "0.0.0-lab11.1-generated"`. The generator's docstring lists what is kept and what is omitted. The optional live mode produces a real plan to compare.

## What you will practise

- Reading a **plan as data**: what is known, what is unknown until apply, and what the configuration says about each.
- **Policy as code** that fails closed: twelve rules on network exposure, private model access, encryption, tags, identity, budgets, resilience and guardrails, with one reviewed **waiver**.
- **Cost from day one**: a fixed-cost estimate per plan, with every price an assumption labelled and dated, and usage-based items listed rather than guessed.
- **Teardown as a tested procedure**: complete, safe for neighbours, and verified by an inventory.
- Measuring a gate on **seeded cases**, including misses and a control.

## How the tests choose what to grade

Tests run against `starter/` by default. `LAB_TARGET=solution python -m pytest -q` (bash) checks the reference. PowerShell: `$env:LAB_TARGET="solution"; python -m pytest -q; Remove-Item Env:LAB_TARGET`. The variable persists until removed, so always remove it, or later runs will silently grade the solution. Run pytest from this lab's folder.

Until you finish, every failing test stops with `NotImplementedError`. `tests/test_relay.py`, `tests/test_data.py` and the provided network rules' tests pass from the start.

## Steps

### 1. Read the incident and the environment (20 min)

Read Chapter 11's opening incident, then `relay-repo/docs/adr/ADR-012` to `ADR-015` and `relay-repo/infra/network.tf`. Draw the subnets and mark which have a route out. Which single security-group rule reaches the internet, and who can reach the thing it belongs to?

### 2. Read a plan as data (25 min)

Open `data/plans/relay-nonprod.plan.json` in an editor that formats JSON. Find `aws_db_instance.relay` in `resource_changes`: which attributes are in `after`, which are `true` in `after_unknown`, and why is `address` unknown? Find `aws_vpc_security_group_egress_rule.proxy_https_internet` and its entry in `configuration`: how would a check know which security group it belongs to? Read the docstring of `starter/cloudcheck/plan.py`, then `check_network` in `policy.py`, which is provided as a worked example.

```bash
cd starter
python -m cloudcheck.report check ../data/plans/relay-nonprod.plan.json
```

Until TODO 1-5 are done this stops with `NotImplementedError`; that is expected.

### 3. Exposure: POL002-POL004 (35 min)

Implement TODO 1, `check_exposure` in `starter/cloudcheck/policy.py`. The docstring is the specification; `tests/test_policy.py` checks each case by hand.

```bash
python -m pytest -q tests/test_policy.py -k "public or model or bucket"
```

### 4. Encryption and tags: POL005-POL006 (35 min)

Implement TODO 2, `check_encryption`, and TODO 3, `check_tags`. Read `tags_all`, not `tags`: the provider's `default_tags` appear only in `tags_all`. Control case C01 exists to catch the mistake.

### 5. Identity: POL007-POL008 (30 min)

Implement TODO 4, `check_identity`. `ecr:GetAuthorizationToken` is the one action allowed on `"*"`: it does not support resource-level permissions. OIDC trust must pin both the audience and the subject.

### 6. Budgets, databases, guardrails: POL009, POL011, POL012 (25 min)

Implement TODO 5, `check_guardrails`. Compare `data/policy.json`'s allowed regions and sizes with `relay-repo/infra/org/scp-*.json`; `tests/test_data.py` checks that they agree.

### 7. Run the checks, the incident and the seeded cases (30 min)

```bash
cd starter
python -m cloudcheck.report check ../data/plans/relay-nonprod.plan.json --gate; echo "exit $?"
python -m cloudcheck.report check ../data/plans/incident-lab.plan.json --gate; echo "exit $?"
python -m cloudcheck.report check ../data/plans/relay-nonprod.plan.json --overlay ../data/seeded/S13.overlay.json --gate; echo "exit $?"
python -m cloudcheck.report check ../data/plans/relay-nonprod.plan.json --as-of 2027-03-01 --gate; echo "exit $?"
python -m cloudcheck.report seeded ../data/plans/relay-nonprod.plan.json --seeded ../data/seeded > ../evidence/seeded.md
```

In PowerShell, use `echo "exit $LASTEXITCODE"`. On Windows PowerShell 5.1, `>` writes UTF-16; use `| Out-File -Encoding utf8 ../evidence/seeded.md` instead.

Why do S13 and S17 exit 2 rather than 0 or 1? What would S15's change look like, and which control sees it? Then write your own case: copy `data/seeded/S02.overlay.json` to `evidence/seeded/S18.overlay.json`, change one value, and run `check` with `--overlay`.

## Troubleshooting

| Symptom | Likely cause |
| --- | --- |
| Every resource fails POL006 on Relay's plan | You read `tags`; read `tags_all`, which includes the provider's default tags. |
| `aws_security_group.*` reported as "cannot check" | Inline rules are unknown because they are computed, not configured. Use `configured()`: only a configured unknown is undecidable. |
| POL004 fires on the incident plan | Only explicit `bedrock:` actions count as model access; `"*"` is POL007's finding. |
| POL007 fires on `aws_kms_key.relay` | Key policies are resource policies, not identity policies; POL007 reads only `IDENTITY_POLICIES`. |
| Fargate cost is 1,024 times too high | `cpu` and `memory` are in CPU units and MiB, as strings: divide by 1,024. |
| The bucket of a public access block is unknown | Use `referring()` or `reference()`: the configuration names the bucket even when its ID is unknown. |
| `test_generator_reproduces_committed_data` fails | Data edited by hand; regenerate with `python scripts/generate_data.py`. |
| Garbled characters in reports | Your console's encoding; save with `Out-File -Encoding utf8` and open in an editor. |

## Optional live mode (not graded; costs money)

`scripts/live_mode.py` runs a real `tofu plan` against **your own** sandbox account, then the checks on the real plan, so you can compare it with the generated one. It can also apply and destroy the environment, with its services at zero tasks and the HTTPS listener excluded. Read the script's docstring before you run anything. It needs `--github-repository` naming **your** repository, because the CI roles trust exactly that repository; the book's placeholder is refused. It refuses to change an account unless you set `LAB11_LIVE=1`, pass `--execute`, `--i-accept-charges`, `--max-usd` of at most 10 and `--hours` of at most 4, and it refuses to apply if the lab's estimator puts the run over your ceiling. The ceiling is an estimate checked before apply, not a cap: nothing stops the environment after the hours you planned, so destroy it yourself and set a budget action in the account.

The script prints its estimate for the reduced environment before it applies, and logs it; the database's creation and deletion each take several minutes and bill while they run. Set a budget alert in the account first. The destroy keeps a final snapshot: delete it afterwards. Record every command, error and cost in `evidence/live/`. The authors have not run the live mode against a real account for this edition; treat it as a reviewed procedure, not a tested one.

**Offline extra, no account needed.** If OpenTofu 1.10 or later is installed, `tofu init -backend=false` then `tofu validate` in a copy of `relay-repo/infra/` checks the configuration's syntax and references without credentials. A `tofu test` file with `mock_provider "aws" {}` can go further and assert planned values with no cloud at all. Neither is required, and CI does not run them.
