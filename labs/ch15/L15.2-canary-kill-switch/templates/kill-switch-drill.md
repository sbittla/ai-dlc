# Kill-switch drill for an AI feature

Copy into `evidence/` and complete.

| | |
| --- | --- |
| Feature | |
| Tripped by (person or automation) and when | |
| Restored by, when, and the reason given | |

## Before the trip

Suggestions served with the feature, overridden, and overridden only because of it. How long did detection take,
and what limited it?

## After the trip

When did the first ticket from a rollout workspace get the stable route? What else had to happen (a release, a
flags change, a message to support)?

## False trips

From the null scenario: how often does the rule trip with no real difference, and what would you change to make
that rarer? What does the change cost in detection time?
