## Brief

From Tuesday 4 May 2027 Relay's releases go out through the pipeline Lab 15.1 builds, and the 15:00 UTC deploy
train is retired. A release no longer reaches every user at once. ADR-047 moves it through steps of 5%, 25%, 50%
and 100% of production traffic, compares the canary with the stable version every minute on Chapter 16's SLOs,
and rolls back by itself when the canary burns its error budget fast and is worse than the stable version. AI
features sit behind flags with kill switches, so a feature that does worse online can be turned off without
rolling back the release.

You will build the canary's minute-by-minute judgement, the rollout that acts on it, and the watch that trips an
AI feature's kill switch, and run them on six release scenarios and two AI-feature scenarios.

**About the data.** Every scenario in `data/` is **synthetic and configured** by `scripts/generate_data.py`: the
traffic rates, error and latency probabilities, the platform incident in R4, the one bad minute in R6, and the
quality of each triage cohort in A1 and A0. `canary/traffic.py` draws per-minute counts and per-ticket outcomes from
those parameters, seeded by scenario and minute, so every run gives the same numbers. The all-at-once comparison
assumes a person needs 15 minutes from detection to the old version serving again. The policies and the kill
switch are Relay 4.29.0's own, copied unchanged from Lab 15.1 into `vendor/`.

## What you will practise

- **Burn rates** per minute, with a minimum number of requests before anything is judged.
- Telling a **bad release** from a **bad day**: both versions burning together is not the release's fault.
- A **progressive rollout** that holds, pages, rolls back or promotes, and what it exposes users to.
- A **kill switch for an AI feature**, tripped by a two-proportion test between cohorts, and the false trips that
  checking every five minutes produces.

## How the tests choose what to grade

Tests run against `starter/` by default. To check the reference, in bash: `LAB_TARGET=solution python -m pytest -q`.
In PowerShell: `$env:LAB_TARGET="solution"; python -m pytest -q; Remove-Item Env:LAB_TARGET`. The variable persists
until it is removed, so always remove it, or later runs will silently grade the solution. Run pytest from this lab's
folder. Until you finish, failing tests stop with `NotImplementedError`.

## Steps

### 1. Read the policy (20 min)

Read ADR-047 (in Lab 15.1's `relay-repo/docs/adr/`), `vendor/config/canary.json` and the two API SLOs in
`vendor/config/slos.json`. What error rate is a burn rate of 14.4 on SLO-API-AVAIL, and on SLO-API-LATENCY?

### 2. One minute's verdict: TODO 1 (45 min)

Implement `minute_verdict` in `analysis.py`. Why is a canary that burns alongside the stable version a hold only
when it is no more than twice as bad? What would the rule do in R4 without the "both" case, and what if the canary
itself overloaded the shared database?

### 3. The rollout: TODO 2 (60 min)

Implement `run_canary` in `rollout.py`, then from `starter/`:

```bash
python -m canary.report rollouts
python -m canary.report rollout --id R2
```

Compare R2 and R3 with the all-at-once column. Then explain R4's "rolled back" under all at once, and R5's
"rolled back: not judged" under the canary. Which of the two is the safer mistake?

### 4. The kill switch: TODO 3 (60 min)

Implement `z_two_proportion`, `feature_verdict` and `watch` in `killswitch.py`, then:

```bash
python -m canary.report feature
python -m canary.report null
```

How long did A1 take to trip, and what limited it? How many of A0's 40 null runs tripped, and why is that more
than 1%?

### 5. Review (55 min)

Fill in `templates/rollout-review.md` for R2 or R4 and `templates/kill-switch-drill.md` for A1. Then change one
number in a copy of the policy (for example, check the AI feature every 60 minutes instead of 5) and say what it
does to A1's trip time and A0's false trips. Do not edit `vendor/`.

## Troubleshooting

- `NotImplementedError: TODO n` — expected until you implement TODO n.
- Results differ from the chapter — check `LAB_TARGET`, then rerun `python scripts/generate_data.py` and
  `git diff data/`; the data must not change.
- `ModuleNotFoundError: relay` — run from `starter/` or `solution/`; the package puts `vendor/` on the path.

## Known limits

Traffic, errors, latency and triage outcomes are drawn from configured probabilities, so the results show how the
rules behave, not how Relay behaves. Relay 4.29.0's service and worker do not yet call `relay.release.flags`
(wiring owned by sam.o, by 2027-05-31), so the kill switch runs here only. The canary compares two versions on the same minute and does not model
caches, sticky sessions or schema changes. The two-proportion test assumes comparable, independent cohorts.
