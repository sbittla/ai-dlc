## Brief

After the leaked-token incident (Chapter 14, a composite), Relay's security lead, aisha.r, asked for a governance pack
for the agents: who may do what, what personal data flows where, what licences the code carries, and where Relay's AI
features fall under the EU AI Act. A coding agent produced a first draft in an afternoon. It reads well. It also
gives an agent the right to approve its own pull requests, leaves traces kept indefinitely, and says Relay is "fully
compliant" with two regulations.

You will build the checks that turn such a draft into evidence a reviewer can rely on: a permission matrix with
separation-of-duties rules (provided, as a worked example), a DPIA check, a licence scan, a first-pass AI Act
classification and an overclaim check. Then you will assemble the pack and review it.

**About the data.** Everything in `data/` is **generated** by `scripts/generate_data.py` and labelled. The "draft"
files stand for the agent's unedited output; the "reviewed" files are the team's versions. The AI Act answers are the
team's, and the classification is the authors' reading of Regulation (EU) 2024/1689 as of November 2026. **Nothing in
this lab is legal advice, and nothing it produces is a compliance claim.** Its output is evidence for qualified people
to review.

## What you will practise

- A **permission matrix** with separation-of-duties rules that hold for people and agents.
- A **DPIA** whose data flows each have a purpose, a basis, a retention period, a residency and a minimization measure.
- A **licence scan** that includes code an agent generated.
- A first-pass **EU AI Act classification** that names the provision behind every answer.
- Writing governance text that **stops short of compliance claims**.

## How the tests choose what to grade

Tests run against `starter/` by default. In bash: `LAB_TARGET=solution python -m pytest -q` checks the reference. In
PowerShell: `$env:LAB_TARGET="solution"; python -m pytest -q; Remove-Item Env:LAB_TARGET`. Always remove the variable
afterwards, or later runs will silently grade the solution. Until you finish, failing tests stop with
`NotImplementedError`.

## Steps

### 1. Read the brief and the data (15 min)

Read Section 14.5 of the chapter. Open `data/aiact/features.json` and `data/dpia/dpia-reviewed.json`.

### 2. The permission matrix (20 min)

```bash
cd starter
python -m govpack.report matrix --draft
python -m govpack.report matrix
```

The matrix has seven non-human identities: the six registered agents that call Relay, and
`detection-automation`, which calls nothing in Relay and acts only through the kill-switch role. Read `matrix.py`.
For each of the draft's six findings, say what could go wrong if it shipped. Why does GOV003 need
two people to hold the approval permission, not one?

### 3. The AI Act classification: TODO 1 (40 min)

Implement `classify_feature` in `aiact.py`, then `python -m govpack.report aiact`. Read Article 5(1)(f), Article 6(3),
Annex III point 4 and Article 50 for yourself. Which feature would change tier if its design changed, and how? Record
the date on which you checked the application dates against EUR-Lex: Regulation (EU) 2026/1744 (the Digital Omnibus
on AI) moved the high-risk dates, and `data/aiact/dates.json` keeps both the original and the amended ones.

### 4. The DPIA: TODO 2 (35 min)

Implement `check_dpia` in `dpia.py`, then run `python -m govpack.report dpia --draft` and `python -m govpack.report
dpia`. Which of the draft's findings would have made the leaked debug log a larger breach?

### 5. Licences: TODO 3 (25 min)

Implement `classify` in `licenses.py`, then `python -m govpack.report licenses`. Why is the AGPL library denied for
Relay when the GPL proxy is only reviewed? What should happen to the generated snippet that matched published code?

### 6. Overclaims: TODO 4 (20 min)

Implement `find_overclaims` in `claims.py`, then `python -m govpack.report claims --draft`. Rewrite each flagged
sentence so that it states what the evidence shows. The checker is a word list: name one overclaim it would miss.

### 7. Assemble and review (25 min)

```bash
python -m govpack.report pack > ../evidence/governance-pack.md
```

On Windows PowerShell 5.1, use `| Out-File -Encoding utf8 ../evidence/governance-pack.md` instead of `>`. Complete
`templates/governance-pack-review.md` and `templates/g4-gate-checklist.md` in `evidence/`.

## Troubleshooting

| Symptom | Likely cause |
| --- | --- |
| F4 comes out "minimal" | Annex III applies when the system profiles people or is not a narrow procedural task; check both. |
| F2 comes out "minimal" | Test "is it an AI system" first; rules written by people are not, on the team's answers. |
| The OR licence is denied | Choose the best option of an OR expression; only AND needs every option. |
| The reviewed pack has overclaims | Skip sentences that negate ("not", "no" as words). |
| DPIA flows report DP007 with no personal data | Only flows that list personal data need a minimization measure. |
