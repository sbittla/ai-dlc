## Brief

On Monday 23 November 2026 a failing CI run printed the evaluation harvester's Relay service token, base64-encoded,
in its debug log, and a CI agent posted that log in a public issue. The token had no expiry. Someone used it on
14 nights over the next three weeks to export Relay's support tickets, and nobody noticed until a customer forwarded
a phishing email on Monday 14 December. Chapter 14 tells the story (a composite).

You have what Relay built afterwards: **Relay 4.23.0** in `relay-repo/`. Its new package `src/relay/audit/` issues
15-minute agent tokens in exchange for proof of the agent's workload, keeps a hash-chained audit trail of agent
actions, redacts secrets and personal data before anything is logged, and has a kill switch.
`governance/agents.json` registers every agent identity, `infra/agents.tf` gives the CI agents their own federated
AWS roles and the kill switch its quarantine policy, and `infra/detection/rules.json` holds four detection rules.

You will build the checks around it: an inventory check for agent credentials, two of the detection rules, an
attribution check on the audit trail, the measurement of a kill-switch drill, and caller scoping with a row budget for
Lab 3.2's query tool, which Chapter 3 left without either.

**About the data.** Everything in `data/` is **generated** by `scripts/generate_data.py`, deterministically, and
labelled as such in every file. The seven-week activity replay is a reconstruction in the shape of Relay's request log;
the misuse pattern, the backfill and the seeded cases were configured in the generator, so the detection results show
what the rules do with those patterns, not discoveries about attackers. The audit trail was written by
`relay.audit` itself. The drills run Relay's real token service in process on a simulated clock, with simulated
agents; the cloud-side steps take **assumed** durations (`data/drill/assumptions.json`). The token in the debug-log
excerpt is fake.

## What you will practise

- Building an **inventory** of every credential an agent uses, and judging it against ten rules.
- **Behavioural baselines** per identity, and alerts that compare against them.
- Checking an **audit trail**: chain, anchors and attribution to an agent and a person.
- Measuring a **kill-switch drill**, and saying which parts are measured and which assumed.
- **Caller scoping**: a tool that knows who is calling and how much they have already read.

## How the tests choose what to grade

Tests run against `starter/` by default. To check the reference, in bash: `LAB_TARGET=solution python -m pytest -q`.
In PowerShell: `$env:LAB_TARGET="solution"; python -m pytest -q; Remove-Item Env:LAB_TARGET`. The variable persists
until it is removed, so always remove it, or later runs will silently grade the solution. Run pytest from this lab's
folder.

Until you finish, failing tests stop with `NotImplementedError`. `tests/test_relay.py`, `tests/test_data.py` and the
tests of provided rules pass from the start.

## Sample of acceptable evidence (excerpt)

> The inventory of 14 December has 27 findings across six credentials and break-glass access; three credentials had
> no expiry, and one, a shared bot account's token, could approve and merge. The inventory of 12 January has none.
> Replayed against 28-day baselines, DR-002 alerts 2 min 50 s after the first misuse, against 20 days 13 hours in the
> incident. One alert in three weeks was a false alarm, an approved backfill, and it would have tripped the
> analytics job automatically. D01, a stolen token used from a GitHub-hosted runner at the harvester's own volume, is
> missed by all four rules; a first-use rule would catch its first export, and a 15-minute token without the export
> scope limits what it could do. In the simulated DRILL-1, a 300-second verification cache kept the token working for
> 210 seconds after the alert. In DRILL-2 the time to revoke on Relay's side is the assumed 4-second trip delay; the
> cloud side's 29 seconds is assumed until a live drill measures it.

## Troubleshooting

| Symptom | Likely cause |
| --- | --- |
| `test_windowed_totals_...` off by one at the window's edge | The window is (at - window, at]: an event exactly one window earlier has left it. |
| Thresholds of 0 for every identity | `windowed_totals` is not keeping separate windows per identity. |
| DR-003 never fires | `sum_rows` rules add `rows`; `count` rules add 1. Pass `use_rows` through. |
| Attribution counts kill-switch records as unattributed | They name an `actor` in `detail`, not a person in `on_behalf_of`. |
| `revocation_seconds` returns a time for DRILL-1 before 210 | Ignore refusals that an acceptance follows; find the refusal after the last acceptance. |
| Scoping reads workspace 2 through `task_id` | Resolve every request with `workspace_of` before running it, and treat `None` as out of scope. |
| `test_generator_reproduces_committed_data` fails | Data edited by hand; regenerate with `python scripts/generate_data.py`. |
| `ModuleNotFoundError: relay` | Run from `starter/` or `solution/`; importing `agentsec` puts `relay-repo/src` and `vendor/` on the path. |

## Known limits

- The token service verifies claims that a verifier has already checked. The verifier for GitHub's OIDC tokens and for
  signed AWS identity requests is a dependency that needs its own ADR and supply-chain review; it is not in 4.23.0.
- Relay's HTTP service does not yet call `TokenService.verify` or write the audit trail; wiring them in is a separate
  change. The registry's enabled flags and epochs live in memory here; production needs them in the database.
- Delegation needs the person's own proof (a subject token from `person_issuer`); the launcher of a session holds
  it while the exchange happens. `restore` checks two names; until Relay's admin path authenticates both people,
  the two-person rule is a check on what the caller says. Tokens are HMAC-signed, so only the token service verifies.
- The inventories record ECS task-role credentials at 3,600 seconds, Relay's policy maximum. That figure is the
  lab's setting, not AWS's: ECS task-role credentials last up to six hours by default (as of November 2026, Appendix F,
  entry F-L04), and Chapter 14's table says ECS rotates them. Read the 3,600 as the limit Relay asks for.
- The cloud side of every drill is assumed. A live drill in your own sandbox account is the only way to measure it;
  this lab has no live mode, and the kill-switch workflow template is illustrative.
